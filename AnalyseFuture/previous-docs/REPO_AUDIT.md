# Upstream repository evaluation

Observed 2026-11-13 for the private browser-proxy implementation. All 19 repositories in [BUILD_VS_REUSE.md](BUILD_VS_REUSE.md) were queried. Integration is selective: the shortlist contains competing implementations and later native products, not a compatible plug-in collection.

This is a source/metadata evaluation, **not an independent security audit**. Read-only Git access, root license files and selected manifests/READMEs were examined. No upstream application was deployed or exhaustively tested by this evaluation. Default HEADs below are observations, not dependency pins or stable-release endorsements.

## Reproducible evidence

For each repository, run `git ls-remote --symref https://github.com/OWNER/REPO.git HEAD`, shallow metadata checkout (`git clone --depth 1 --filter=blob:none --no-checkout ...`), `git log -1 --format='%H %cI %s'`, and retrieve the license over HTTPS at the exact commit. Git/curl used inherited proxy/CA trust with verification enabled. HEAD dates are author-controlled maintenance signals, not proof of support or absence of vulnerabilities. GitHub API returned HTTP 403, so archival flags, release/security-advisory coverage and issue response times were not verified.

## Selected minimal integration

The local proof of concept integrates **proxy-chain 3.0.3** (Apache-2.0) as the established HTTP/CONNECT forwarding engine and **ipaddr.js 2.3.0** (MIT) for address classification. Custom code supplies account/session/grant policy, destination validation, quota enforcement and Chrome lifecycle integration; it does not invent a tunnel or encryption protocol. Node/OpenSSL provides TLS and cryptography. The extension uses official Manifest V3 proxy/auth APIs directly. Playwright 1.65.0 is selected for browser verification.

## Capability gates

A library advertising HTTPS does not prove this project's transport configuration, grant revocation, quota, DNS rebinding defense or browser fail-closed behavior; those need repository integration tests. Live US location, founder-device installation, full-device VPN, store distribution and recurring-cost claims remain separate acceptance gates. Do not expose a prototype gateway publicly until release blockers are closed.
