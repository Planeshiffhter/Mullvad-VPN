# Ownership, licensing and third-party source

- The goal is a company-owned product with original branding, configuration and custom implementation.
- **Public visibility does not by itself grant an open-source license to this repository's contents.** No whole-project LICENSE has been selected or issued in this documentation commit.
- Contributors must not assume they can relicense upstream code, delete notices or mix copyleft/restrictive dependencies into a planned distribution without review.
- Before copying code, record upstream repository URL, exact commit/release, SPDX license, copyright and NOTICE obligations, dependency licenses and intended distribution model.
- For GPL/AGPL/MPL and mixed-license dependencies, investigate applicable obligations and whether use as a separate service changes them; ask for specialized legal review for ambiguous cases.
- Prefer a clean API integration with existing services where it meets needs rather than wholesale vendor code import.
- Screenshots, logos and names of competitor services are for comparative reference only; do not copy their branding or proprietary materials.
- An explicit project-license decision is required before inviting code contributions intended to be broadly reused/distributed. Any contributor agreement or contribution licensing terms require owner review.

This page is process guidance, not legal advice.
