No duplicates were discarded and no historical source/workflow/prompt became active.

“Integration testing every file” has two meanings here: every archived payload receives complete preservation/reference verification; executable features are tested through their maintained active counterparts. Plans, historical reports, legal text and the Word document do not become executable features. Their table rows explicitly say preservation-only.

## What the source comparison established

- The 20 previous-code originals already have active counterparts: 18 differ by source/import/asset/command paths, one browser test is byte-identical, and one development suite also lacks the two newer occupied-port regressions. No unique implementation was found to restore.
- The pre-validation gateway copy lacks the current startup-cleanup correction; restoring it would lose the tested fix. Its old runtime test copy lacks those regression cases.
- Native reuse, country/city/server selection, eligibility/health and competitor comparisons are research/design. Proposed types/algorithms in a Markdown chapter are not a running selector or fleet.
- The preserved Word knowledge archive is a research document. ZIP CRC/OOXML checks validate its format, not a tunnel, location or networking implementation. Archived validation commands remain historical and are not executed.
- Real native Linux/Windows/macOS/Android builds, Firefox support, a live authorized exit and owner-device leak acceptance remain unestablished. Native ZIPs stay untouched in upstream/archives.

## Honest test boundaries and remaining work

The active cross-component suite obtains a real TLS control-API grant, forwards controlled traffic through the real proxy, verifies accounting/revocation and restores encrypted SQLite state; separate runtime tests exercise startup/stop/restart/occupied ports and account recovery. These are meaningful integration checks for the implemented counterparts, not execution of old copies.

Two actual MV3/Chrome proxy tests are expected to skip if the managed unpacked-extension block remains. The separate popup runtime is simulated; dashboard/browser DOM tests and Node TLS integration have different boundaries. Preserve browser policies and TLS verification. No live US location, OS VPN tunnel, complete DNS/WebRTC/IPv6 leak prevention, public customers, signed update service or native-device acceptance is asserted.

The dashboard exhausted-grant display discrepancy remains an open presentation issue: server authorization rejects exhausted quota while UI uses only expiry/revocation. This structural task does not change application logic. Keep that fix separate from archive moves.

Next engineering work: actual extension acceptance on an authorized runner; the bounded dashboard regression/fix; one source/license/toolchain-reviewed Linux native build; then an independently authorized endpoint and real per-OS routing/DNS/failure proof. Owner spending, hosting, signing/publication and licensing decisions remain prerequisites.
