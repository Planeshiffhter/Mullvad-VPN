UPSTREAM SOURCE INVENTORY AND FUNCTIONAL CATALOG
Prepared: 17 November 2026

Scope: every ZIP central-directory entry in the two preserved source archives,
including every nested regular file, directory and symlink. Archive bytes were
read offline; no archived script, hook, application or build command was run.

Catalog: docs/repository/UPSTREAM_CATALOG.jsonl (one JSON object per entry).
The catalog records the original archive path, preserved internal path,
recreated build/upstream equivalent, type/size, content SHA-256 for files,
symlink target text, functional category/module, and bounded dependency clues.
Repeated archive_sha256 identifies the repository-preserved archive bytes,
not an upstream signature, trusted revision or distribution permission.

METHOD AND LIMITS
Functional labels use actual module and nested path roles, including native
daemon, CLI, routing/DNS/firewall/WireGuard, Android libraries, Apple tunnel
extensions, Electron desktop UI, Qt/QML client, privileged service, server
provisioning, recipes, release tooling, tests, assets, documentation and notices.
These are structural/lexical classifications, not a manual semantic audit of
every implementation. An import/include is evidence of a literal reference,
not proof that a dependency is present, safe, buildable or dynamically used.

Dependency references are deduplicated and capped at 16 per entry; each
record includes unique_literal_references, cap and truncated. The scan reads
recognized UTF-8 source/manifests up to 1 MiB; a NUL byte marks binary data.
Skipped/unrecognized/non-UTF8 outcomes are explicit. Cargo/package manifests
receive dependency-name parsing; source patterns collect representative Rust
use, C/C++ includes, Swift/Kotlin/Java/Python/JS imports, QML imports, CMake
packages/includes, Gradle project/artifact and Go import references. This is
not a resolved transitive graph, version audit, include-path resolver, license
conclusion or security review. Generated code/runtime imports may be missed.

WHY VENDOR INTERNAL STRUCTURE IS PRESERVED
The archived module paths participate in Cargo workspaces, relative source
imports, Gradle/Conan/CMake/Xcode builds, resource references, submodules and
platform tooling. Relocating individual vendor files would risk breaking
these contracts and losing provenance. The project groups intact source ZIPs
under upstream/archives and recreates independent native trees under ignored
build/upstream; files stay in their original vendor-relative positions.
Licenses/notices and branding assets are preserved, without assuming rights
to copy trademarks, redistribute binaries or relicense third-party code.
Original vendor AGENTS/CLAUDE/CI files are cataloged as preserved source
material, not current instructions to execute untrusted code.

Neither native application is established as built or runtime-verified by
this inventory. Vendor account APIs, release keys, servers and update
infrastructure are not supplied as our operated product by these archives.
Archive/source checksums do not establish that a reported account compromise
was investigated or remediated.
